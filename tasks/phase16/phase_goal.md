# Phase 16 Goal: Roadmap Triage For Optional Depth

## Goal

Convert the remaining implied roadmap items into explicit decisions before adding more breadth.

Phase 16 is not a commitment to implement every listed protocol or vendor-like surface. It exists to decide which optional depth is worth implementing next, which should remain a contract/mock, and which should stay out of scope.

## Product Outcome

- Future standards have a ranked implementation/defer decision.
- Hospitality-specific adjacent flows such as intercom, control-panel faults, BMS hardening, and comfort telemetry have clear scope boundaries.
- Generic smart-home and building-automation evaluators can see which future features are likely to land and why.
- NOT A HOTEL-like evaluators can see that the roadmap still tracks their operating realities without claiming private compatibility.

## Non-Goals

- Implementing Phase 16 features before Phase 15 hardening is complete.
- Turning roomci into a full vendor emulator.
- Claiming compatibility with any private company environment.
