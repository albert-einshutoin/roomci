# Task 05: Public Hospitality Debrand

## Status

`todo`

## Problem

Public docs contain too many vendor and specific-company signals. This makes
the project look like a private-company portfolio artifact instead of a
general Smart Home / Building Automation QA emulator.

## Scope

- Keep hospitality as a domain pack and evaluator example.
- Replace public-facing vendor name lists with generic integration classes
  such as backup WAN, intercom API, SIP/phone provider, access-control system,
  CAD/BIM tool, and identity provider.
- Preserve honest non-goals: this is not a full private-stack emulator and not
  a vendor emulator.

## Acceptance Criteria

- README and canonical docs describe the product without relying on specific
  private-company or vendor name-dropping.
- Domain-pack docs explain what is covered, mocked, deferred, and rejected in
  reusable terms.
