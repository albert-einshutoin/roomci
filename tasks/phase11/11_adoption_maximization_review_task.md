# Task 11 — Adoption Maximization Review

## Goal

Run a strict adoption review before declaring Phase 11 complete, focused on whether `roomci` is likely to be shortlisted by both NOT A HOTEL and broader IoT/SmartHome teams.

## Review Questions

- Would a NOT A HOTEL engineer see domain understanding without feeling private compatibility is being overclaimed?
- Would a generic IoT/SmartHome engineer understand how to map their own specs?
- Is the first-run path fast enough to evaluate without a meeting?
- Are protocol limitations visible before they become surprises?
- Do reports show value to software, field, and operations stakeholders?
- Does the product have enough external endpoint depth to feel like an emulator, not only a scenario runner?
- Is there a clear next step from demo to internal PoC?

## Implementation Scope

- Review README, docs, examples, tasks, and generated reports from an evaluator perspective.
- Score the product across:
  - category clarity
  - Not A Hotel relevance
  - generic IoT/SmartHome relevance
  - protocol credibility
  - first-run experience
  - PoC handoff readiness
  - evidence quality
- File follow-up tasks for gaps instead of marking Phase 11 done prematurely.

## Acceptance Criteria

- Review produces a concrete score and top remaining blockers.
- Any claim that cannot be backed by implementation, docs, or command output is removed or weakened.
- Phase 11 is only marked done if the product can credibly ask for a real company evaluation.
